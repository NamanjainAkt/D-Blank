# Performance Optimization Plan for Landing Page

The current landing page is experiencing lag due to heavy 3D rendering, excessive GSAP ScrollTrigger instances, and expensive CSS filters (large blurs). This plan aims to make the experience smooth while maintaining the cyberpunk aesthetic.

## 1. GSAP & ScrollTrigger Optimization
- **Centralize Plugin Registration**: Move `gsap.registerPlugin(ScrollTrigger)` to a central utility file or the main layout to avoid multiple registrations.
- **Batch Animations**: Update `AnimatedContent.tsx` to support batching if multiple instances are used within the same container, reducing the number of `ScrollTrigger` instances.
- **Debounce Resize**: Ensure `ScrollTrigger.refresh()` is called efficiently.
- **Reduced Motion**: Implement `window.matchMedia('(prefers-reduced-motion: reduce)')` to disable or simplify animations for users who prefer it.

## 2. 3D Model Optimization (`HeroModels.tsx`)
- **Memory Management**: Ensure all Three.js objects (geometries, materials, textures) are properly disposed of when the component unmounts.
- **Lighting Refinement**: Reduce the number of `PointLight` instances in the scene. Use a single `RectAreaLight` or optimized `DirectionalLight` where possible.
- **Frustum Culling**: Ensure models aren't being rendered when they are out of view (though they are in the hero section, they might still process during scroll).
- **Material Optimization**: Update `applyBrandMaterials` in `three-brand.ts` to use a shared material registry. Currently, it clones materials for every mesh, which creates unnecessary memory overhead and prevents draw call batching.
- **Geometry Consolidation**: If possible, use `BufferGeometryUtils.mergeGeometries` or similar techniques to reduce the number of draw calls for the models.

## 3. CSS & Rendering Optimization
- **Blur Filters**: Replace expensive `blur-[80px]` and `blur-[100px]` filters with pre-rendered SVG filters or CSS `radial-gradients`. Large blurs are particularly taxing on mobile GPUs.
- **Scanline Animation**: Add `will-change: transform` to the scanline div to promote it to its own compositor layer.
- **Layer Consolidation**: Use `isolation: isolate` on sections to prevent unnecessary layer repaints.

## 4. Component Refactoring
- **Typing Animations**: Refactor `TypingText.tsx` to use a more efficient animation method than creating a GSAP timeline entry for every single character.
- **Redundant Footers**: Merge `Footer.tsx` and `Footer2.tsx`. `Footer2` is currently acting as a stylized branding section, while `Footer` is the functional footer. They should be integrated or one should be removed if redundant.
- **Micro-components**: Audit `GameplayPreview` and other micro-components in `FeatureCard` to ensure they are not running animations when not visible.

## 5. Next.js & Asset Optimization
- **Image Optimization**: Ensure all images use `next/image` with appropriate sizes and priorities.
- **Dynamic Imports**: Keep `HeroModels` as a dynamic import but ensure it doesn't block the main thread during initialization.

## Verification Plan
- **Performance Audit**: Use Chrome DevTools (Performance tab) to measure Frame Rate and Main Thread activity during scroll.
- **Lighthouse**: Run Lighthouse audits to check for performance score improvements.
- **Memory Leak Check**: Monitor heap snapshots to ensure Three.js is correctly disposing of resources.
- **Device Testing**: Verify smoothness on both high-end and low-end devices.
